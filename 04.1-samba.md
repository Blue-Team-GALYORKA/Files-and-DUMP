# Практическая работа №4.1. Настройка файлового сервера Samba

## Цель работы
- Научиться настраивать сервер Samba.
- Понимать, как составляется конфигурационный файл Samba и его параметры.
- Понять, как работает iptables.

## Задача
- Получить доступ к файлам на файловом сервере Linux клиентом Linux.
- Получить доступ к файлам на файловом сервере Linux клиентом Windows.
- Добавить сервис Samba в автозагрузку.
- Настроить ресурс `share`: чтение для группы `users`, запись для группы `admins` и
  пользователя `PT`.
- (Доп.) Настройка корзины для общего ресурса; пояснить `smbstatus`, вывод записать в .txt.

> Стенд: 3 ВМ — Unix-сервер, Unix-клиент, Windows-клиент. Сделать snapshot каждой после базовой настройки.
> 📷 СКРИНШОТ: каждый шаг.

## Ход работы

### 1. Установка Samba (на сервере)
```bash
sudo apt-get update
sudo apt-get install -y samba samba-client
```

### 2. Добавить Samba в автозагрузку
```bash
sudo systemctl enable smbd nmbd
sudo systemctl start smbd nmbd
sudo systemctl status smbd        # active (running)
```

### 3. Резервная копия конфига
```bash
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak
```

### 4. Создать каталоги и группы
```bash
sudo mkdir -p /samba/share
sudo groupadd users
sudo groupadd admins
```
Создать пользователя PT и добавить пользователей в группы:
```bash
sudo useradd -M -s /sbin/nologin PT      # -M без домашнего каталога, вход запрещён
sudo usermod -aG admins PT               # PT также в admins
# примеры рядовых пользователей
sudo useradd user1 && sudo usermod -aG users user1
sudo useradd admin1 && sudo usermod -aG admins admin1
```
Задать Samba-пароли (отдельная база паролей Samba):
```bash
sudo smbpasswd -a PT
sudo smbpasswd -a user1
sudo smbpasswd -a admin1
```

### 5. Права на каталог
```bash
sudo chgrp -R users /samba/share
sudo chmod -R 2775 /samba/share   # 2 = setgid, чтобы новые файлы наследовали группу
```

### 6. Настроить ресурс share в smb.conf
```bash
sudo nano /etc/samba/smb.conf
```
В конец файла добавить блок:
```ini
[share]
   comment = Общий ресурс
   path = /samba/share
   browseable = yes
   read only = yes
   ; чтение для группы users
   valid users = @users @admins PT
   ; запись разрешена только admins и пользователю PT
   write list = @admins PT
   create mask = 0664
   directory mask = 2775
```
Пояснение параметров:
- `read only = yes` + `write list` — по умолчанию только чтение, запись только для
  перечисленных в `write list` (группа `@admins` и пользователь `PT`);
- `valid users` — кому вообще виден ресурс;
- `@имя` — означает группу.

### 7. Проверить конфиг и перезапустить
```bash
testparm                       # проверка синтаксиса smb.conf
sudo systemctl restart smbd nmbd
```
📷 СКРИНШОТ вывода `testparm`.

### 8. Доступ клиентом Linux
```bash
smbclient -L //192.168.1.50 -U PT          # список ресурсов
smbclient //192.168.1.50/share -U PT       # подключение
# внутри: ls, get файл, put файл (запись доступна PT), exit
```
Или смонтировать как каталог:
```bash
sudo apt-get install cifs-utils
sudo mount -t cifs //192.168.1.50/share /mnt -o username=PT
```
📷 СКРИНШОТ доступа с Linux-клиента.

### 9. Доступ клиентом Windows
В проводнике Windows в адресной строке ввести:
```
\\192.168.1.50\share
```
Ввести логин `PT` и Samba-пароль. Проверить, что user1 (группа users) может только
читать, а PT/admin1 — записывать.
📷 СКРИНШОТ доступа из Windows.

### 10. Команда smbstatus и запись вывода в файл
```bash
sudo smbstatus
sudo smbstatus > ~/smbstatus.txt
cat ~/smbstatus.txt
```
`smbstatus` показывает активные подключения к Samba: пользователей, с каких IP, какие
ресурсы открыты и заблокированные файлы. Разделы вывода:
- **Samba version** — версия;
- **PID Username Group Machine** — кто подключён;
- **Service pid Machine Connected at** — к каким ресурсам;
- **Locked files** — какие файлы заблокированы.
📷 СКРИНШОТ smbstatus и файла smbstatus.txt.

### 11. (Доп.) Корзина для общего ресурса
Добавить в блок `[share]` модуль recycle:
```ini
   vfs objects = recycle
   recycle:repository = .recycle
   recycle:keeptree = yes
   recycle:versions = yes
```
Удалённые файлы будут попадать в скрытый каталог `/samba/share/.recycle`.
Перезапустить: `sudo systemctl restart smbd`.

### 12. iptables — разрешить порты Samba
```bash
sudo iptables -A INPUT -p tcp --dport 445 -j ACCEPT   # SMB
sudo iptables -A INPUT -p tcp --dport 139 -j ACCEPT   # NetBIOS
sudo iptables -A INPUT -p udp --dport 137 -j ACCEPT
sudo iptables -A INPUT -p udp --dport 138 -j ACCEPT
sudo iptables -L -n                                   # посмотреть правила
```

## Контрольные вопросы
- **Где хранится конфиг Samba?** — `/etc/samba/smb.conf`.
- **Как задать запись только для группы?** — `write list = @admins` при `read only = yes`.
- **Что означает `@` перед именем?** — группа пользователей.
- **Зачем smbpasswd?** — Samba хранит свою базу паролей отдельно от системной.
- **Что показывает smbstatus?** — активные подключения, ресурсы и заблокированные файлы.
- **Какие порты у SMB?** — 445 (TCP), 139 (TCP), 137–138 (UDP, NetBIOS).

Настроен файловый сервер Samba с ресурсом `share`: чтение для группы `users`, запись для

Linux- и Windows-клиентов, рассмотрены `smbstatus`, корзина (vfs recycle) и открытие
портов через iptables.
