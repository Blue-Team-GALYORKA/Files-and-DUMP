# Практическая работа №4.3. Fail2Ban и защита от DoS/DDoS на примере nginx

## Цель работы
Научиться конфигурировать Fail2Ban для отражения атак DoS/DDoS на nginx.

## Задача
- Организовать простую тестовую DoS-атаку.
- Защитить сервер встроенными возможностями nginx.
- Защитить сервер с помощью Fail2Ban + iptables (автоматически).
- Защитить сервер с помощью Fail2Ban + ipset (автоматически).

> ⚠️ Нагрузочное тестирование проводится **только** на собственном учебном стенде.
> Стенд: сервер Debian с nginx + машина-генератор нагрузки. 📷 СКРИНШОТ каждого шага.

---

## 1. Установка nginx (Debian)
Подключение официального репозитория nginx:
```bash
sudo apt install curl gnupg2 ca-certificates lsb-release debian-archive-keyring
curl https://nginx.org/keys/nginx_signing.key | gpg --dearmor \
  | sudo tee /usr/share/keyrings/nginx-archive-keyring.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
http://nginx.org/packages/debian $(lsb_release -cs) nginx" \
  | sudo tee /etc/apt/sources.list.d/nginx.list
sudo apt update
sudo apt install nginx
sudo systemctl enable --now nginx
```
Проверка: `curl -I http://localhost` → `HTTP/1.1 200 OK`.
📷 СКРИНШОТ стартовой страницы nginx.

## 2. Простая тестовая DoS-атака
Варианты генерации нагрузки с машины-атакующего:
```bash
# вариант с ab (Apache Benchmark)
sudo apt-get install apache2-utils
ab -n 100000 -c 500 http://192.168.1.50/

# вариант с siege
sudo apt-get install siege
siege -b -c 255 -t 60s http://192.168.1.50/

# примитивный цикл curl
while true; do curl -s http://192.168.1.50/ >/dev/null; done
```
Во время атаки на сервере видно рост запросов в логе `/var/log/nginx/access.log` и
нагрузку в `htop`.
📷 СКРИНШОТ нагрузки до защиты.

## 3. Защита встроенными средствами nginx (rate limiting)
В `/etc/nginx/nginx.conf` в блок `http { }` добавить зону ограничения:
```nginx
# не более 10 запросов в секунду с одного IP
limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;
# не более 10 одновременных соединений с одного IP
limit_conn_zone $binary_remote_addr zone=addr:10m;
```
В блок `server { }` (или `location /`) сайта:
```nginx
location / {
    limit_req  zone=one burst=20 nodelay;
    limit_conn addr 10;
}
```
Проверить и перезагрузить:
```bash
sudo nginx -t
sudo systemctl reload nginx
```
При превышении лимита nginx отвечает `503 Service Temporarily Unavailable`.
📷 СКРИНШОТ ответов 503 при повторной атаке.

## 4. Защита через Fail2Ban + iptables
### Фильтр для nginx
Создать `/etc/fail2ban/filter.d/nginx-dos.conf`:
```ini
[Definition]
failregex = ^<HOST> -.*"(GET|POST).*
ignoreregex =
```
### Jail
В `/etc/fail2ban/jail.local` добавить:
```ini
[nginx-dos]
enabled   = true
port      = http,https
filter    = nginx-dos
logpath   = /var/log/nginx/access.log
# 300 запросов за 60 секунд → бан на 10 минут
maxretry  = 300
findtime  = 60
bantime   = 600
action    = iptables-multiport[name=nginx-dos, port="http,https", protocol=tcp]
```
Применить:
```bash
sudo systemctl restart fail2ban
sudo fail2ban-client status nginx-dos
```
После повторной атаки IP генератора нагрузки будет автоматически заблокирован в iptables:
```bash
sudo iptables -L -n | grep 192.168.1.XX
```
📷 СКРИНШОТ забаненного IP в iptables.

## 5. Защита через Fail2Ban + ipset (эффективнее для многих IP)
ipset хранит заблокированные адреса в хеш-таблице ядра — одно правило iptables вместо
сотен, что критично при DDoS с множества адресов.
```bash
sudo apt-get install ipset
```
Изменить `action` в jail на ipset-вариант:
```ini
action = iptables-ipset-proto6[name=nginx-dos, port="http,https", protocol=tcp]
```
Применить и проверить:
```bash
sudo systemctl restart fail2ban
sudo ipset list                 # посмотреть набор заблокированных IP
```
📷 СКРИНШОТ `ipset list` с заблокированными адресами.

## 6. Сравнение методов
| Метод | Где работает | Плюсы | Минусы |
|-------|-------------|-------|--------|
| nginx limit_req | уровень приложения | гибко, отдаёт 503 | не блокирует сам IP |
| Fail2Ban + iptables | уровень сети | блокирует IP автоматически | медленно при тысячах правил |
| Fail2Ban + ipset | уровень сети | быстро, тысячи IP в одном правиле | чуть сложнее настройка |

## Контрольные вопросы
- **Что такое DoS/DDoS?** — отказ в обслуживании из-за перегрузки сервиса запросами (DDoS — с множества источников).
- **Как ограничить частоту запросов в nginx?** — директивы `limit_req_zone`/`limit_req` и `limit_conn`.
- **Чем ipset лучше чистого iptables при DDoS?** — хранит множество IP в одном правиле ядра, работает быстрее.
- **Что отвечает nginx при превышении лимита?** — `503 Service Temporarily Unavailable`.
- **Как Fail2Ban узнаёт об атаке?** — анализирует `/var/log/nginx/access.log` по фильтру.

## Вывод
Отработаны три уровня защиты веб-сервера nginx от DoS/DDoS: ограничение частоты запросов
средствами самого nginx (rate limiting, ответ 503), автоматическая блокировка IP через
Fail2Ban + iptables и масштабируемая блокировка через Fail2Ban + ipset. На тестовой атаке
показано срабатывание каждого механизма.
