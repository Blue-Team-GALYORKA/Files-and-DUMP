# Практическая работа №4.2. Fail2Ban-SSH и защита от brute-force

## Цель работы
Научиться конфигурировать Fail2Ban для отражения атак brute-force на SSH.

## Задача
- Настроить сервер SSH.
- Установить и настроить Fail2Ban.
- Научиться пользоваться Hydra.
- Провести с помощью Hydra brute-force атаку (на **своём** учебном стенде).
- Повторить атаку при выключенном Fail2Ban и с IP, исключённым из бан-листа.

> ⚠️ Hydra применяется **только** на собственной изолированной учебной ВМ. Подбор
> паролей к чужим системам незаконен. Цель работы — проверить, что защита (Fail2Ban)
> действительно блокирует перебор.
> Стенд: сервер Linux с SSH + атакующая машина (Kali). 📷 СКРИНШОТ каждого шага.

---

## Теория
Fail2Ban читает log-файлы сервисов и по заданным правилам (фильтрам) блокирует по IP
источники подозрительной активности, например многократных неудачных входов по SSH.
Блокировка выполняется через iptables на заданное время.

---

## Ход работы

### 1. Настроить SSH-сервер (кратко, подробно — ПР 2.2)
```bash
sudo apt-get install openssh-server
sudo systemctl enable --now ssh
```

### 2. Установить Fail2Ban
```bash
sudo apt-get update
sudo apt-get install fail2ban
sudo systemctl enable --now fail2ban
sudo systemctl status fail2ban        # active (running)
```

### 3. Создать локальный конфиг (не трогая jail.conf)
> `jail.conf` перезаписывается при обновлениях, поэтому настройки кладут в `jail.local`.
```bash
sudo nano /etc/fail2ban/jail.local
```
Содержимое:
```ini
[DEFAULT]
# адреса, которые никогда не банятся (белый список)
ignoreip = 127.0.0.1/8 192.168.1.10
# время бана (сек), 600 = 10 минут
bantime  = 600
# окно, за которое считаются попытки
findtime = 600
# сколько неудачных попыток до бана
maxretry = 3

[sshd]
enabled  = true
port     = 2222
logpath  = %(sshd_log)s
backend  = systemd
```
Пояснение: при 3 неудачных входах за 10 минут IP блокируется на 10 минут; адреса из
`ignoreip` не блокируются никогда.

### 4. Применить настройки
```bash
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd
```
Вывод покажет фильтр sshd, количество найденных и забаненных IP.
📷 СКРИНШОТ `fail2ban-client status sshd`.

### 5. Установить Hydra (на атакующей машине)
```bash
sudo apt-get install hydra
```
Подготовить словари (для демонстрации — короткие):
```bash
echo -e "root\nadmin\nkali\ntest" > users.txt
echo -e "123456\npassword\nqwerty\nkali\nadmin" > pass.txt
```

### 6. Провести brute-force атаку по SSH
```bash
hydra -L users.txt -P pass.txt -t 4 -f ssh://192.168.1.50:2222
```
Опции: `-L` список логинов, `-P` список паролей, `-t 4` потоки, `-f` остановиться при
первом успехе. При включённом Fail2Ban после нескольких попыток соединения начнут
отклоняться (IP забанен).
📷 СКРИНШОТ вывода Hydra.

### 7. Убедиться, что IP забанен
На сервере:
```bash
sudo fail2ban-client status sshd
sudo iptables -L -n | grep 192.168.1.XX    # IP атакующего в DROP/REJECT
```
📷 СКРИНШОТ забаненного IP.

### 8. Разбанить IP вручную
```bash
sudo fail2ban-client set sshd unbanip 192.168.1.XX
```

### 9. Повторить атаку с выключенным Fail2Ban
```bash
sudo systemctl stop fail2ban
```
Добавить IP атакующего в `ignoreip` (исключить из бана) либо просто остановить сервис, затем:
```bash
hydra -L users.txt -P pass.txt -t 4 ssh://192.168.1.50:2222
```
Теперь атака не блокируется, и при наличии слабого пароля Hydra его найдёт:
```
[2222][ssh] host: 192.168.1.50   login: kali   password: kali
```
Вывод очевиден: **без Fail2Ban перебор проходит беспрепятственно**, с Fail2Ban —
блокируется после нескольких попыток.
📷 СКРИНШОТ результата без защиты.

### 10. Вернуть защиту
```bash
sudo systemctl start fail2ban
```

---

## Контрольные вопросы
- **Что делает Fail2Ban?** — банит по IP источники подозрительной активности на основе логов.
- **Почему настройки кладут в jail.local?** — `jail.conf` перезаписывается при обновлениях.
- **Что задают maxretry/findtime/bantime?** — число попыток, окно их подсчёта и длительность бана.
- **Как не забанить себя?** — добавить свой IP в `ignoreip`.
- **Как разбанить IP?** — `fail2ban-client set sshd unbanip IP`.
- **Какой вывод из сравнения с/без Fail2Ban?** — без защиты brute-force успешен при слабом пароле; Fail2Ban блокирует перебор.

## Вывод
Настроена защита SSH от перебора паролей с помощью Fail2Ban (3 попытки → бан на 10 минут).
Утилитой Hydra продемонстрирована атака brute-force: при включённом Fail2Ban атакующий IP
блокируется, при выключенном — перебор проходит и слабый пароль подбирается. Это
подтверждает эффективность Fail2Ban.
