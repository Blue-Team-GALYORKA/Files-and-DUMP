# Практическая работа №2.3. Настройка SSH-authorized_keys

## Цель работы
- Научиться настраивать SSH-authorized_keys.
- Научиться работать с ключами SSH.

## Задача
- Разобраться, как работает доступ по ключам.
- Организовать аутентификацию к серверу Linux через ключи.
- Организовать аутентификацию к серверу Linux через ключи без пароля.

> Стенд: клиент (локальная машина) и сервер Linux (из ПР 2.2).
> 📷 СКРИНШОТ: каждый шаг.

---

## Теория
Пара ключей SSH состоит из **закрытого** (приватного, хранится у клиента, секретен) и
**открытого** (публичного, кладётся на сервер). Сервер проверяет, что у клиента есть
приватный ключ, не передавая сам ключ по сети. Это надёжнее пароля, который можно
подобрать брутфорсом. Открытый ключ клиента на сервере хранится в
`~/.ssh/authorized_keys`.

---

## Ход работы

### 1. Сгенерировать пару ключей на клиенте
```bash
ssh-keygen -t rsa -b 4096
```
- Запрос места: по умолчанию `~/.ssh/id_rsa` (нажать Enter).
- Запрос парольной фразы (passphrase): можно оставить пустой для входа без пароля.

Создаются два файла:
```
~/.ssh/id_rsa       # закрытый ключ (НИКОМУ не передавать)
~/.ssh/id_rsa.pub   # открытый ключ
```
Проверка:
```bash
ls -l ~/.ssh
```
📷 СКРИНШОТ сгенерированных ключей.

### 2. Скопировать открытый ключ на сервер
Самый простой способ — `ssh-copy-id`:
```bash
ssh-copy-id -i ~/.ssh/id_rsa.pub kali@192.168.1.50 -p 2222
```
Утилита запросит пароль пользователя на сервере (один раз) и допишет открытый ключ в
`~/.ssh/authorized_keys` на сервере.

Ручной способ (если ssh-copy-id недоступен):
```bash
cat ~/.ssh/id_rsa.pub | ssh kali@192.168.1.50 -p 2222 \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

### 3. Проверить вход по ключу
```bash
ssh kali@192.168.1.50 -p 2222
```
Если passphrase не задавали — вход произойдёт **без запроса пароля**.
📷 СКРИНШОТ входа без пароля.

### 4. (Опционально) вход совсем без пароля через ssh-agent
Если задавали passphrase, её можно вводить один раз за сессию:
```bash
eval $(ssh-agent)
ssh-add ~/.ssh/id_rsa
```
Далее все подключения в рамках сессии — без повторного ввода.

### 5. Включить аутентификацию по ключам на сервере
В `/etc/ssh/sshd_config` убедиться, что включено:
```
PubkeyAuthentication yes
AuthorizedKeysFile  .ssh/authorized_keys
```
Перезапустить сервер:
```bash
sudo systemctl restart ssh
```

### 6. (Для PuTTY) конвертация ключа в формат .ppk
PuTTY использует формат PPK, несовместимый с OpenSSH. Конвертация утилитой **PuTTYgen**:
1. Запустить PuTTYgen → **Load** → выбрать `id_rsa` (показать все файлы).
2. **Save private key** → получить `.ppk`.
3. В PuTTY: *Connection → SSH → Auth → Credentials* → указать `.ppk`.
📷 СКРИНШОТ PuTTYgen и настройки PuTTY.

## Контрольные вопросы
- **Какой ключ хранится на сервере?** — открытый (`id_rsa.pub`) в `~/.ssh/authorized_keys`.
- **Какой ключ секретный?** — закрытый (`id_rsa`), остаётся у клиента.
- **Чем вход по ключу безопаснее пароля?** — приватный ключ не передаётся по сети и не подбирается брутфорсом.
- **Зачем passphrase, если есть ключ?** — защищает файл приватного ключа на случай его кражи.
- **Как скопировать ключ на сервер одной командой?** — `ssh-copy-id`.

Доступ по ключам надёжнее парольного, так как исключает передачу секрета по сети.
